# Releasing the `mvt` command line tool

The `Release` workflow builds the macOS `mvt` archive, uploads it to the GitHub
release, and opens a Homebrew formula pull request.

## One-time setup

The workflow uses the `COMMITTER_TOKEN` repository secret to create a branch and
pull request in `Outdooractive/homebrew-tap`.

Create a token with write access to that repository and save it as
`COMMITTER_TOKEN` in the `Outdooractive/mvt-tools` Actions secrets:

- **Fine-grained token:** repository access to `Outdooractive/homebrew-tap`,
  with `Contents: Read and write` and `Pull requests: Read and write`.
- **Classic token:** `repo` and `workflow` scopes.

The tap repository's `main` branch is currently unprotected, but the workflow
intentionally opens a pull request instead of pushing directly. The token must
be able to create a branch in `homebrew-tap`; the tap CI deliberately skips pull
requests from forks.

## Normal release

1. Make sure `main` is green and the version changes are merged.
2. Create and push an annotated tag:

   ```bash
   git tag -a v3.1.0 -m "mvt-tools 3.1.0"
   git push origin v3.1.0
   ```

3. Create a GitHub release for the tag and publish it.
4. The `Release` workflow now runs automatically:
   - builds a universal macOS `mvt` binary;
   - uploads `mvt.tar.gz` to the release;
   - opens a Homebrew formula PR in `Outdooractive/homebrew-tap`.
5. Wait for the tap's **Formula** workflow to pass.
6. Review and merge the formula PR.

After the formula PR is merged:

```bash
brew update
brew upgrade mvt-tools
mvt --version
```

Do not upload `mvt.tar.gz` manually. Re-running the workflow overwrites the
existing asset.

## Prereleases

Prerelease tags such as `v3.1.0-beta.1` still get a release archive, but the
Homebrew formula PR is skipped. Homebrew should only point at stable releases.

## Manual backfill

Use the `Release` workflow for releases that were published before the
automation existed, or to retry a failed release:

```bash
scripts/trigger-release.sh v3.1.0
```

Without an argument, the script uses the newest tag reachable from
`origin/main`. You can also trigger it from the GitHub UI:

1. Open **Actions → Release**.
2. Choose **Run workflow**.
3. Enter the tag name.
4. Run it.

If the archive was uploaded but the formula PR step failed, fix the
`COMMITTER_TOKEN` secret and re-run the failed Homebrew job.

## Troubleshooting

- **No release asset:** check the `Release` workflow run and confirm the tag
  contains the current release workflow.
- **No formula PR:** confirm `COMMITTER_TOKEN` exists and still has write access
  to `homebrew-tap`. Re-run the failed `Open Homebrew formula PR` job.
- **Tap CI fails:** inspect the formula PR. Release asset URLs and checksums are
  generated by the build job and passed to the formula action.
